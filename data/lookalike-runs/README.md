# lookalike benchmark — raw audit trail

Everything the lookalike benchmark needs for **full third-party reproducibility** lives in this folder. Each file here is generated by `scripts/run_lookalike_benchmark.py` and is committed alongside the snapshot in `data/latest-lookalike.json`.

## Layout

```
data/lookalike-runs/
└── <dataset_slug>/                 # e.g. lookalike-2026-q2
    └── <seed_slug>/                # e.g. servicetitan
        ├── <vendor_slug>.json      # slim per-cell artifact — used by the UI
        └── <vendor_slug>.raw.json  # full audit trail — every config, every HTTP call, every judge call
```

For every (seed × vendor) cell on the leaderboard there are **two** files. The slim `<vendor_slug>.json` carries the cell value the UI shows; the heavier `<vendor_slug>.raw.json` carries the bytes a third party would need to verify that cell from scratch.

## Slim format — `<vendor>.json`

The minimum needed to render a row in the matrix. Only the winning config's normalized candidates and judge verdicts are persisted.

```json
{
  "dataset_slug": "lookalike-2026-q2",
  "seed_slug": "pylon",
  "provider_slug": "predictleads",
  "config_name": "default",
  "config": {                              // winning config (the one that maxed P@K)
    "name": "default",
    "use_paging": false
  },
  "k": 10,
  "relevant_count": 10,
  "precision_at_k": 100.0,
  "latency_ms": 708,
  "cost_usd": null,
  "judge_model": "gpt-5.4-mini",
  "judged_at": "2026-06-07T02:00:42Z",
  "candidates": [
    {
      "name": "Frill.co",
      "domain": "frill.co",
      "description": "Customer-feedback platform...",
      "rank": 1,
      "extra": { "linkedin_url": "...", "employee_count": 12 },
      "relevant": true,                    // panel verdict, by strict majority
      "anchor_match": true,                // cleared the hard anchor gate
      "capabilities_matched": [            // any-of overlap with the seed's capabilities
        "payments", "online ordering"
      ],
      "rationale": "Anchor true: restaurant POS platform; overlaps payments and online ordering.",
      "votes": [                           // per-judge breakdown behind the majority
        { "judge_model": "claude-opus-5",  "relevant": true,  "rationale": "..." },
        { "judge_model": "gpt-5.6-terra",  "relevant": true,  "rationale": "..." },
        { "judge_model": "kimi-k3",        "relevant": false, "rationale": "..." }
      ]
    },
    ... 9 more
  ],
  "error": null
}
```

## Raw format — `<vendor>.raw.json`

The full audit trail. Captures **every config the orchestrator swept** (not just the winner) and, per config, **every HTTP round-trip** plus **every judge round-trip**.

```json
{
  "dataset_slug": "lookalike-2026-q2",
  "seed_slug": "pylon",
  "seed_input": {                          // exact inputs the orchestrator handed each vendor
    "seed_name": "Pylon",
    "seed_domain": "usepylon.com",
    "description": "B2B customer support platform...",
    "category": "b2b-saas"
  },
  "provider_slug": "predictleads",
  "provider_name": "PredictLeads",
  "k": 10,
  "winning_config_name": "default",        // which attempt the orchestrator kept
  "judge_model": "gpt-5.4-mini",
  "captured_at": "2026-06-07T02:00:51Z",

  "attempts": [
    {
      "config": { "name": "default", "use_paging": false },

      // Every HTTP call the runner made for this config. Auth headers
      // redacted; URLs + bodies are full-fidelity.
      "vendor_calls": [
        {
          "method": "GET",
          "url": "https://predictleads.com/api/v3/companies/usepylon.com/similar_companies",
          "request_headers": {
            "X-Api-Key": "***REDACTED***",
            "X-Api-Token": "***REDACTED***",
            "Accept": "application/json",
            "User-Agent": "openfunnel-bench/0.1 ..."
          },
          "request_body": null,            // GET — no body
          "response_status": 200,
          "response_body": { ... full raw JSON the vendor returned ... },
          "elapsed_ms": 708
        }
      ],

      // The normalized candidates the runner extracted from the raw
      // response — these are exactly what the judge saw, one-per-row,
      // in the same order.
      "extracted_candidates": [
        { "name": "...", "domain": "...", "description": "...", "rank": 1, "extra": {...} },
        ... K candidates
      ],

      // Every LLM round-trip. One per judge per candidate, so a gated
      // three-model panel emits two calls for an agreed candidate and three
      // when the first two disagree. `messages` is the literal prompt;
      // `raw_response` is the JSON the model emitted before pydantic parsing.
      //
      // The `relevant` flag published in the slim file is NOT taken from the
      // model: it is recomputed in code from `anchor_match` and
      // `capabilities_matched`, so a judge cannot mark a candidate relevant
      // while failing the anchor.
      "judge_calls": [
        {
          "model": "gpt-5.6-terra",
          "messages": [
            { "role": "system", "content": "You are an evaluator...\n\nSEED:\n  ANCHOR (hard requirement): ...\n  CAPABILITIES (match any subset): ..." },
            { "role": "user", "content": "CANDIDATE:\n  name: ...\n  ..." }
          ],
          "raw_response": "{\"anchor_match\":true,\"capabilities_matched\":[...],\"relevant\":true,\"rationale\":\"...\"}",
          "parsed_response": {
            "anchor_match": true,
            "capabilities_matched": ["payments", "online ordering"],
            "relevant": true,
            "rationale": "Anchor true: restaurant POS platform; overlaps payments and online ordering."
          },
          "elapsed_ms": 1744,
          "for_candidate_rank": 4,
          "error": null,
          "cached": false                  // true when reused from the in-run verdict cache
        },
        ... one per judge × candidate
      ],

      "result": {
        "status": "ok",                    // ok | vendor_crash | vendor_error | no_candidates | judge_crash
        "k": 10,
        "relevant_count": 10,
        "precision_at_k": 100.0,
        "latency_ms": 708,
        "judged_at": "2026-06-07T02:00:42Z",
        "cost_usd": null,
        "error": null
      }
    },
    ... one entry per swept config (e.g. OpenFunnel has 4: seed_only_agentic, seed_only_semantic, seed_plus_query_agentic, seed_plus_query_semantic)
  ]
}
```

## What's redacted

Only **auth credentials** get scrubbed. The redacted header allow-list is in `scripts/lookalike/common.py`:

```
x-api-key, x-api-token, authorization, x-auth-token, x-token, api-key, apikey
```

URLs, request bodies, response bodies, and judge prompts are persisted **verbatim**. None of our vendors put credentials in URLs or bodies, so there is nothing to scrub there. (If you add a vendor that does, extend the redaction layer in `_redact_headers()` or extend the dataclass to scrub URL query params.)

## Reproducing any single cell

For any cell on the leaderboard, you can independently reproduce the result in two ways:

### 1. Re-issue the same vendor call

Lift `vendor_calls[0]` from the raw file. Swap `***REDACTED***` for your own credentials. Hit the URL with the same body. Diff the response against `response_body` in the raw file. (Companies move in and out of vendor indexes over time — exact match is not guaranteed, but the top-K should be substantially overlapping for a stable index.)

### 2. Re-issue the same judge call

Lift any `judge_calls[i].messages` from the raw file. Send those literal messages to **any** Chat Completions–compatible LLM (OpenAI, Anthropic via converter, local Llama, your own fine-tune). Compare your model's verdict against `judge_calls[i].parsed_response.relevant` to measure judge drift.

This is the open-source "audit trail" claim: every Precision@K number on the leaderboard is backed by a literal HTTP envelope you can re-run and a literal LLM prompt you can re-score with a different judge to measure bias.
